# Code of Conduct

## Our standard

VEXA contributors and maintainers are expected to keep project spaces constructive, technical, and respectful. Disagreement about design, benchmarks, security, or implementation is welcome when it addresses the work rather than the person.

Examples of expected behavior include giving actionable review feedback, stating uncertainty and evidence clearly, respecting different experience levels, crediting prior work, and correcting mistakes without hostility.

Unacceptable behavior includes harassment, threats, discriminatory or demeaning language, sexualized attention, deliberate intimidation, sustained personal attacks, publishing another person's private information, or disrupting project spaces after being asked to stop.

## Scope

This code applies in repository issues, pull requests, discussions, reviews, and other spaces where someone is representing the VEXA project.

## Enforcement

Project maintainers may edit, hide, reject, or remove contributions and may restrict participation when behavior violates this code. Enforcement should be proportionate to the conduct and should prioritize the safety of affected participants.

For conduct that can safely be discussed in public, use the relevant repository moderation/reporting controls. For harassment, threats, doxxing, or other reports that contain sensitive personal information, do not post the details publicly; contact the repository owner through an available private GitHub contact channel or use GitHub's platform reporting mechanisms.

Anyone handling a private conduct report should share its contents only as needed to investigate and respond.
